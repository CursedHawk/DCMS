## Harness: what had broken since 10-12, and what is new

The suite had stopped working against current master in four places; all fixed in this commit.

- **`Idempotency-Key` required** on a person's writes to admin-api (ADR 0024): every seeder call and
  k6 admin write got `400 idempotency-key-required`. `lib/api.mjs` and the probe now send one per
  write; `lib/k6.js` exports `writeKey()` and each scenario's admin write spreads it.
- **`starter-files?flavor=starter` → `?template=content`** (Mode B seeding).
- **`GET /api/admin/content` is paged**: `provision.mjs` read page one only, so a re-run re-created
  every slug past it (409). It now follows `nextCursor`.
- **Record totals stop at 5,000**: `dynamic-apps.mjs` took the capped total as the row count and
  re-imported (unique violations). It now finds the last page. The fixtures' site-user cookies had
  also expired (the first `dynamicapps` step: 29.6 % errors, all signed-in site checks); re-running
  the seeder refreshes them.
- Probe: past the ceilings, import (1,001 rows) and bulk update (501 ids) now **run as jobs** (202 +
  `jobId`) rather than 400. Checks updated; this run still reported them as failures.

New: `scenarios/analytics.js` (beacon through the site's own domain with a browser UA, a dashboard
poller, and a teardown that waits for ingest and reports `analytics_drain_ms` / `analytics_stored`);
`provision.mjs` enables analytics (instance `insights`; `analytics` is a reserved slug); probe section
`scripts` adds table `script_jobs` + flow `script_score` to `crm` on first use.

**Reading analytics numbers:** k6's `req/s` divides by the whole run *including teardown's drain
wait*, so `stress.sh`'s rate understates the beacon. Use `analytics_stored / ~145 s` for accepted/s.
